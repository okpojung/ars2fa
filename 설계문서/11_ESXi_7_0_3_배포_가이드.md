# 11. ESXi 7.0.3 Host 배포 가이드

## 1. 목적

이 문서는 `ars2fa` MVP를 ESXi 7.0.3 Host 위에 배포하는 방법을 설명한다.

ars2fa 초기 운영은 API 사용 앱 100개 이내를 기준으로 하며, 아래 구성을 권장한다.

```text
ESXi 7.0.3 Host
  └── Ubuntu Server VM
        ├── Docker
        ├── Coolify
        ├── ars2fa frontend
        ├── ars2fa backend
        ├── PostgreSQL
        └── Redis
```

초기 단계에서는 단일 VM + Coolify 구성이 가장 단순하다. API 사용 앱이 늘어나면 PostgreSQL, Redis, Worker를 별도 VM으로 분리한다.

## 2. 전체 배포 흐름

```text
1. ESXi에서 Ubuntu Server VM 생성
2. Ubuntu Server 설치
3. 고정 IP 설정
4. SSH 보안 설정
5. Docker 설치
6. Coolify 설치
7. DNS 설정: ars2fa.baro.me -> 서버 공인 IP
8. GitHub 저장소 연결
9. PostgreSQL/Redis 생성
10. Backend 배포
11. Frontend 배포
12. 관리자 계정 seed
13. SSL/도메인/헬스체크 확인
14. 백업 설정
```

## 3. 권장 VM 사양

### 3.1 초기 운영

| 항목 | 권장 |
|---|---|
| vCPU | 4 vCPU |
| RAM | 8 GB 이상 |
| Disk | SSD/NVMe 100 GB 이상 |
| OS | Ubuntu Server 22.04 LTS 또는 24.04 LTS |
| Network | 고정 IP |
| 용도 | Coolify + Frontend + Backend + PostgreSQL + Redis |

인증 로그 보관 기간이 길거나 API 호출량이 빠르게 증가하면 RAM 16 GB, Disk 200 GB 이상을 권장한다.

### 3.2 확장 시 분리 기준

| 상황 | 조치 |
|---|---|
| DB 디스크 사용량 증가 | PostgreSQL 별도 VM 분리 |
| Redis memory 증가 | Redis 별도 VM 분리 |
| CSV/통계 작업 지연 | Worker 별도 컨테이너 또는 VM 분리 |
| Backend 응답 지연 | Backend replica 추가 |

## 6. 고정 IP 설정

Ubuntu에서 네트워크 인터페이스 이름을 확인한다.

```bash
ip addr
```

예: `ens192`

Netplan 파일을 수정한다.

```bash
sudo nano /etc/netplan/00-installer-config.yaml
```

예시:

```yaml
network:
  version: 2
  ethernets:
    ens192:
      addresses:
        - 192.168.94.130/24
      routes:
        - to: default
          via: 192.168.94.1
      nameservers:
        addresses:
          - 8.8.8.8
          - 1.1.1.1
```

적용:

```bash
sudo netplan apply
```

확인:

```bash
ping -c 3 192.168.94.1
ping -c 3 8.8.8.8
ping -c 3 github.com
```

## 8. SSH 보안 설정

운영 서버는 SSH 비밀번호 로그인을 끄고 SSH Key 기반 접속을 권장한다.

### 8.1 로컬 PC에서 SSH Key 생성

```bash
ssh-keygen -t ed25519 -C "ars2fa-admin" -f ~/.ssh/id_ed25519_ars2fa
```

공개키 확인:

```bash
cat ~/.ssh/id_ed25519_ars2fa.pub
```

### 8.2 서버에 공개키 등록

서버에서:

```bash
mkdir -p ~/.ssh
nano ~/.ssh/authorized_keys
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
```

### 8.3 SSH 포트 변경

```bash
sudo nano /etc/ssh/sshd_config
```

권장 설정:

```conf
Port 2222
PasswordAuthentication no
PubkeyAuthentication yes
PermitRootLogin no
ClientAliveInterval 60
ClientAliveCountMax 3
```

방화벽 반영:

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 2222/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
sudo systemctl restart ssh
```

새 터미널에서 접속 확인:

```bash
ssh ubuntu@192.168.94.130 -p 2222 -i ~/.ssh/id_ed25519_ars2fa
```

Coolify에서 Application을 추가한다.

```text
New Resource
  -> Application
  -> Public Repository 또는 GitHub Repository
```

설정:

| 항목 | 값 |
|---|---|
| Name | `ars2fa-backend` |
| Repository | `okpojung/ars2fa` |
| Branch | `main` |
| Build Pack | Dockerfile |
| Dockerfile Location | `apps/backend/Dockerfile` |
| Port | `3000` |
| Domain | `https://ars2fa.baro.me` |

Backend는 `/api/*`, `/v1/ars/*`, `/health`, `/api-docs`를 제공한다.

### 16.1 Backend 환경변수

Coolify Application의 Environment Variables에 아래 값을 설정한다.

```env
NODE_ENV=production
PORT=3000
APP_URL=https://ars2fa.baro.me
ADMIN_URL=https://ars2fa.baro.me/admin
DATABASE_URL=postgresql://ars2fa:{PASSWORD}@ars2fa-postgres:5432/ars2fa?schema=public
REDIS_URL=redis://ars2fa-redis:6379
JWT_SECRET=충분히_긴_랜덤_문자열
SESSION_COOKIE_NAME=ars2fa_session
API_KEY_HASH_SECRET=충분히_긴_랜덤_문자열
PHONE_HASH_SECRET=충분히_긴_랜덤_문자열
LEGACY_ARS_ENABLED=false
LEGACY_ARS_BASE_URL=https://barocall.baro.so
LEGACY_ARS_INSTALL_ANDROID=/install_app.php
LEGACY_ARS_INSTALL_IOS=/install_app_ios.php
LEGACY_ARS_CONFIRM_ANDROID=/confirm_auth.php
LEGACY_ARS_CONFIRM_IOS=/confirm_auth_ios.php
LEGACY_ARS_RECHECK=/confirm_auth_recheck.php
SEED_ADMIN_EMAIL=admin@ars2fa.baro.me
SEED_ADMIN_PASSWORD=강력한_초기_관리자_비밀번호
```

운영에서 실제 ARS 서버를 호출하려면 충분히 검증한 뒤:

```env
LEGACY_ARS_ENABLED=true
```

로 변경한다.

### 16.2 Backend 배포 후 DB migration

### 17.2 라우팅 주의사항

Frontend와 Backend가 같은 도메인을 사용하므로 Coolify proxy에서 아래 path가 Backend로 전달되어야 한다.

```text
/api/*
/v1/ars/*
/health
/api-docs
```

그리고 나머지는 Frontend로 전달한다.

```text
/*
/admin/*
```

Coolify에서 path 기반 라우팅 설정이 어렵다면 초기에는 아래 중 하나를 선택한다.

### 방법 A: Backend도 frontend nginx 뒤로 proxy

Frontend nginx 설정에서 `/api`, `/v1`, `/health`, `/api-docs`를 backend 내부 주소로 proxy한다.

### 방법 B: API 서브도메인 사용

초기 운영 편의를 위해 아래처럼 분리할 수 있다.

```text
https://ars2fa.baro.me        -> Frontend
https://api.ars2fa.baro.me    -> Backend
```

다만 설계 기본안은 단일 도메인 path 기반이다.

## 18. 단일 도메인 path 기반 권장 Proxy 구조

```text
ars2fa.baro.me
  ├── /             -> frontend
  ├── /admin        -> frontend
  ├── /api          -> backend
  ├── /v1/ars       -> backend
  ├── /health       -> backend
  └── /api-docs     -> backend
```

Coolify에서 이 구성이 복잡하면 Nginx Proxy Manager를 별도 VM 또는 같은 VM에 설치해 path routing을 담당시킬 수 있다.


## 24. 장애 대응

### 24.1 Backend health 실패

```bash
curl https://ars2fa.baro.me/health
```

확인 항목:

- backend 컨테이너 실행 상태.
- DATABASE_URL 연결.
- REDIS_URL 연결.
- migration 적용 여부.

### 24.2 로그인 실패

확인 항목:

- `SEED_ADMIN_EMAIL`.
- `SEED_ADMIN_PASSWORD`.
- seed 실행 여부.
- JWT_SECRET 설정 여부.

### 24.3 API Key 인증 실패

확인 항목:

- 신청이 승인 상태인지.
- API Key 상태가 ACTIVE인지.
- `mobile_app_name`이 신청 앱명과 정확히 같은지.
- `client_platform`이 승인 플랫폼과 같은지.
- Android package name 또는 iOS bundle id가 일치하는지.

### 24.4 ARS provider 오류

확인 항목:

- `LEGACY_ARS_ENABLED`.
- `LEGACY_ARS_BASE_URL`.
- install/confirm/recheck path.
- 외부 네트워크 연결.
- provider timeout.

## 26. 배포 완료 기준

아래가 모두 충족되면 ESXi 7.0.3 Host 배포가 완료된 것으로 본다.

- Ubuntu VM이 고정 IP로 동작한다.
- Docker와 Coolify가 정상 동작한다.
- PostgreSQL/Redis가 Coolify에서 healthy 상태이다.
- Backend가 `/health`에 정상 응답한다.
- Frontend가 사용자 포털과 `/admin` 라우트를 정상 표시한다.
- DB migration과 seed가 완료되었다.
- 관리자 승인 후 API Key가 발급된다.
- mock ARS install/confirm 흐름이 인증 로그에 저장된다.
- 백업 정책이 설정되어 있다.
